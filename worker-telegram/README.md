# komnata1908-telegram worker

Отдельный Cloudflare Worker, который принимает заявки на бронирование
с формы на сайте и пересылает их в Telegram-чат администраторов бара
через Bot API. Специально сделан отдельным воркером от
`komnata1908-admin`, чтобы баг здесь не мог сломать страницу `/admin`,
и наоборот.

## Деплой

```bash
cd worker-telegram
npm install -g wrangler   # если ещё не установлен
wrangler login

# секреты (не попадают в репозиторий):
wrangler secret put TELEGRAM_BOT_TOKEN   # токен бота, выданный @BotFather
wrangler secret put TELEGRAM_CHAT_ID     # id чата/группы, куда слать заявки
wrangler secret put ALLOWED_ORIGIN       # один или несколько доменов через запятую, например:
                                          # https://komnata1908.ru,https://www.komnata1908.ru

wrangler deploy
```

После деплоя Cloudflare даст адрес вида
`https://komnata1908-telegram.<account>.workers.dev`. Если он
отличается от уже используемого, его нужно прописать в
`src/utils/bookingApi.js` (константа `PROXY_API`) на фронтенде и
пересобрать сайт.

## Как это работает

- Единственный маршрут — `POST /` (без пути): принимает JSON
  `{ name, tel, date, time, guests, utm }`, собирает из этих полей
  HTML-сообщение и отправляет его через Telegram Bot API
  (`sendMessage`) в чат `TELEGRAM_CHAT_ID`.
- `name` и `tel` обязательны — без них запрос отклоняется с
  `400 { ok: false, error: "missing_fields" }`.
- Все строковые поля обрезаются по длине (`name` — 100 символов,
  `tel` — 40, `date` — 40, `time` — 20, `guests` — 10) и экранируются
  (`escapeHtml`) перед вставкой в HTML-сообщение — защита от
  HTML-инъекции в тело сообщения Telegram.
- Если в теле запроса передан объект `utm` с полями
  `utm_source`/`utm_medium`/`utm_campaign`/`utm_content`/`utm_term` —
  они добавляются в сообщение отдельным блоком.
- Если Telegram API ответил ошибкой — воркер возвращает клиенту
  `502 { ok: false, error: "telegram_error" }`. Заявка в Google
  Таблицу, которую фронтенд отправляет тем же действием пользователя,
  но отдельным независимым запросом (см. `submitToSheet` в
  `src/utils/bookingApi.js` в корне репозитория), при этом не
  пострадает.

## Защита от чужих запросов

У этого воркера нет пароля/токена — единственная защита это проверка
заголовка `Origin`: запрос принимается, только если `Origin`
совпадает с одним из значений в `ALLOWED_ORIGIN` (через запятую).
Запрос без заголовка `Origin` (например, простой `curl` без явного
указания заголовка, или сервер-сервер запрос) или с посторонним
доменом получает `403 Forbidden`. Так же обрабатывается `OPTIONS`
(preflight) — оно всегда отвечает быстро, без обращения к Telegram.

Это не защита от спама/накрутки заявок с самого разрешённого домена
(rate limiting здесь не реализован) — если это станет проблемой,
стоит добавить его отдельно (например, через Cloudflare Rate Limiting
Rules на уровне зоны, без изменения кода воркера).

## Особенность текущей конфигурации

На проде `ALLOWED_ORIGIN` заведён как **секрет**
(`wrangler secret put`), а не как обычная переменная (`vars` в
`wrangler.jsonc`) — хотя по смыслу это не секретное значение (просто
домен сайта), исторически он был задеплоен именно так. Пересоздавать
из-за этого ничего не нужно, но если будете разворачивать воркер с
нуля — проще вынести `ALLOWED_ORIGIN` в `vars` в `wrangler.jsonc`
(код в `src/index.js` читает его одинаково через `env.ALLOWED_ORIGIN`
независимо от того, секрет это или обычная переменная).
